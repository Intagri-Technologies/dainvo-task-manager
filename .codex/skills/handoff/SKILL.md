# Handoff

Write a handoff document summarising the current conversation so a fresh agent
can continue the work.

## Where it goes

`${TMPDIR:-/tmp}/dainvo-handoffs/YYYY-MM-DD-<slug>.md`

Outside the workspace on purpose: a routine handoff is scratch, and this
workspace has a history of scratch files settling at the repo root. Create the
directory if it does not exist, and tell the user the full path — the next
session cannot read your context, only this file.

A fresh session can find recent handoffs with
`ls -t "${TMPDIR:-/tmp}/dainvo-handoffs/"`.

If the work is worth keeping rather than resuming, it is not a handoff. Put it
in the owning project's docs, or use the `research` skill.

## What it must contain

Do not duplicate what other artifacts already hold — specs, plans, ADRs,
migrations, commits, diffs. Reference them by path and let the next agent open
them.

Do record, because none of it survives in a file otherwise:

- **The goal**, as the user stated it, not as you reformulated it.
- **Uncommitted state, per repo.** This is the single most important section
  here. Work in this workspace routinely sits uncommitted across several repos
  at once. Name each repo touched, what is dirty in it, and whether it is
  staged. `git -C <repo> status --short` for each.
- **Checks run and their real results**, including failures and anything not
  run. A check you skipped is information; a check you claim passed but did not
  run is a trap for the next agent.
- **Pre-existing breakage** you found but did not cause, so the next agent does
  not chase it as a regression.
- **Decisions already made and closed**, so they are not relitigated — and the
  reasoning, not just the outcome.
- **What is genuinely unfinished**, separated from what merely looks unfinished.

## Suggested next steps

End with a short section naming which skills the next agent should invoke, and
for what. Name them plainly (`research`, `domain-modeling`,
`writing-for-agents`) rather than describing how to invoke them: Claude Code and
Codex load skills differently, and the next reader may be either.

## Before you write it

Redact secrets: API keys, tokens, passwords, connection strings, and personal
data. Provider payloads and log excerpts in this workspace routinely carry auth
headers — quote only the lines that carry the signal.

Note that a `PreToolUse` hook blocks pushes and branch creation for both agents,
so the next session cannot land the work either. Say what still needs the user.

If the user passed arguments, treat them as a description of what the next
session will focus on and tailor the document to that.
